# Правка перевода руками

Машинный перевод можно перебить в любой момент, не дожидаясь нового прогона модели.
Правки хранятся в `config/manual_overrides.csv` и подставляются **поверх** кэша
на шаге `xlat.apply`, поэтому повторные прогоны их не затирают.

## Формат

```csv
key,ru
game/system|msg_item_collection|419|name,"Хвост баннита"
```

`key` — адрес строки в игре, четыре поля через `|`:

| Поле | Что это | Пример |
|---|---|---|
| путь | путь каталога таблицы (как у события или группы) | `evt/ev01`, `game/field` |
| таблица | имя таблицы внутри файла (у многотабличных файлов их несколько) | `msg_ev01030100`, `msg_item_collection` |
| строка | номер строки таблицы (с нуля или с единицы — как в исходном файле) | `419` |
| колонка | имя текстовой колонки | `name` |

Текст можно заключать в кавычки (обязательно, если внутри есть запятая или перенос
строки — многострочные реплики так и хранятся).

## Инструмент

```powershell
cd tools

python -m xlat.manual find "Хвост ловкого"        # поиск по оригиналу и переводу
python -m xlat.manual set --src "Dextrous Bunnit Tail" --ru "Хвост баннита"
python -m xlat.manual set --key "game/system|msg_item_collection|419|name" --ru "..."
python -m xlat.manual list                        # все правки и отличия от кэша
python -m xlat.manual unset --src "Dextrous Bunnit Tail"
```

* `--src` сопоставляется с исходным текстом строки: сначала точное совпадение, если
  такого нет — поиск по подстроке. Если подходящих строк несколько, инструмент
  покажет их и попросит уточнить `--key`.
* `list` помечает правки, которые бесполезны (значение совпало с кэшем) или ссылаются
  на отсутствующую строку.

## Правила

1. **Разметка сохраняется.** Теги вида `[ML:line ]`, `[XENO:...]`, `<...>`, вставки
   `%s`, `{0}` и подобные должны совпадать с английским оригиналом (по нему идёт
   перевод). Валидатор пропускает строку в сборку только при совпадении тегов.
2. **Переносы строк — один в один.** Число `\n` в переводе равно числу `\n`
   в оригинале: игра располагает текст по этим разрывам, лишний перенос ломает вёрстку.
3. **Термины — по глоссарию** (`config/glossary.csv`). Если термин нужно изменить,
   правьте глоссарий, а не отдельную строку.
4. **Имена собственные** людей не переводим, а транслитерируем кириллицей
   (`Tetsuya Takahashi` → `Тэцуя Такахаси`). Названия компаний и стилизованные
   подписи остаются латиницей (`MONOLITH SOFTWARE INC.`, `ACE (TOMOri Kudo, CHiCO)`).
5. **Названия предметов** строятся как `<качество> <часть> <существо в род. падеже>`:
   качество относится к предмету, а не к зверю. Правильно: «Хвост баннита»,
   «Белая печень раны». Неправильно: «Хвост ловкого баннита» — такого зверя в игре нет.
6. **Обращение** — «ты» к друзьям и ровесникам, «вы» к тем, кто по статусу выше или
   незнаком (подробнее в `config/style_ru.md`).
7. **Смысл важнее английской формулировки.** Если английская локализация что-то
   потеряла, ориентируйтесь на японский оригинал (`ref` в корпусе) — перевод идёт
   с английского, но японский остаётся источником смысла.

## После правок — пересобрать

```powershell
cd tools
python -m xlat.apply
python -m xlat.pack
python -m xlat.dist
```

Правки применяются на шаге `apply`; `pack` пересобирает только изменённые таблицы,
`dist` обновляет пакеты и `INSTALL.md`.

## Как прислать правку в проект

1. Внесите изменения через `python -m xlat.manual set` (или прямо в CSV).
2. Пересоберите и обновите выжимку: `python -m xlat.export`.
3. Пришлите pull request с изменениями `config/manual_overrides.csv`,
   `translations/ru.jsonl` (и `config/glossary.csv`, если правили термины).

В описании правки полезно указать, где строка встречается в игре (глава, квест,
меню), чтобы её было легко проверить.
