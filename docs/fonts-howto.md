# Как править шрифты Xenoblade Chronicles 3 руками

Всё ниже проверено на реальной игре (Eden, апдейт 2.2.1). Инструменты: `tools/fontfix`
(`audit` / `dump` / `import` / `build`) и `tools/ardpack` (правка архива).

## 0. Где что лежит

| Что | Путь |
|---|---|
| Шрифты внутри архива | `/menu/font/{ascii,standard,talk}.wifnt` (+ CJK-варианты, их не трогаем) |
| Оригиналы, извлечённые из архива | `work/font/extracted/menu/font/` |
| Пропатченные (с кириллицей) | `work/font/patched/` |
| Инструмент шрифтов | `tools/fontfix/target/release/fontfix.exe` |
| Патчер архива | `tools/ardpack/target/release/ardpack.exe` |
| Мод-каталог Eden | `work/emulator/eden/user/sdmc/atmosphere/contents/010074F013262000/romfs/` |
| Скрипт скриншота | `work/scripts/cap.ps1` |

## 1. Анатомия `.wifnt` (формат LAFT, версия 10001)

- Ячейка глифа: **37 × 42** px (`glyph_area_width+1` × `glyph_area_height+1`).
- В строке атласа: `standard` — 50 ячеек, `talk` — 49, `ascii` — 13.
- Строк в атласе: `ceil(число глифов / в_строке)`; высота текстуры = `строк × 42`.
- Атлас: **R8Unorm** (1 байт на пиксель), в файле лежит *свизленным*
  (block-linear) и с 40-байтовым футером с магией `LBIM`; `fontfix` де/свизлит сам.
- **Атлас хранит SDF (знаковое поле расстояний), а не «покрытие»**:
  край глифа приходится на значение **≈128**, а яркость меняется примерно на
  **30 единиц на пиксель** расстояния (`value = 128 + d·k`, `d` — знаковое расстояние
  в пикселях). Именно поэтому латинские глифы в `dump` выглядят «мыльными»:
  это не баг дампа, а сам формат — плавные рампы, 94 % пикселей в полутонах.
  Замеры: у латинской `A` максимум **196**, у `H` — 191 (максимум зависит от толщины
  штриха: у толстого штриха расстояние до края больше).
- Глиф = запись в `font_info`: `codepoint (u16), left_x (u8), width (u8)`.
  **Индекс записи = позиция ячейки в атласе.** Руками индексы не трогаем — за это
  отвечают команды `build`/`import`.
- Метрики игрового шрифта (замерено по глифу `H`):
  высота капса **28 px**, базовая линия — **36-я строка** ячейки (из 42),
  отступ слева `pad_left = 3`, справа `pad_right = 0`,
  `global_width_reduction = 4`, `line_height = 20`.
- **Осторожно с «пиком 255»**: если нарисовать глифы как покрытие (плоские плато
  до 255), кириллица выглядит резче и жирнее латиницы и хуже масштабируется при
  изменении размера текста — потому что у игры SDF. `build` теперь сам пишет SDF
  (`--sdf auto` измеряет наклон по игровым `H`/`A`/`o`).

## 2. Диагностика: что есть, чего нет

```
tools/fontfix/target/release/fontfix.exe audit work/font/extracted/menu/font/*.wifnt
```
Печатает по каждому файлу: число глифов, размеры текстуры/ячейки, формат и наличие
обязательных наборов (`ASCII`, `А-я`, `Ё`, `ё`, `«»`, `—`, `…`, `’`, nbsp).

## 3. Посмотреть атлас или одну ячейку

```
FF=tools/fontfix/target/release/fontfix.exe
$FF dump work/font/patched/standard.wifnt work/verify/atlas-standard.png            # весь атлас 1:1
$FF dump work/font/patched/standard.wifnt work/verify/glyph-A-ru.png --glyph U+0410 # ячейка, x6 (222×252)
```
Открывать любым редактором (Paint.NET, Photoshop, Krita, GIMP). Для ручной правки
удобнее ячейка ×6.

## 4. Быстрый путь: собрать кириллицу из TTF

```
$FF build work/font/extracted/menu/font/standard.wifnt assets/fonts/NotoSans-SemiBold.ttf \
     work/font/patched/standard.wifnt --peak auto --dilate 0 --y-shift 0 --x-shift 0
```
- `--peak auto` — подгон яркости под латиницу (обязательно, иначе буквы «жирнее»).
- `--dilate N` — утолщение на N пикселей (если TTF тоньше игрового шрифта).
- `--y-shift` / `--x-shift` — сдвиг кириллицы целиком (подгон по базовой линии).
- TTF — любой: положи в `assets/fonts/` и передай путь (пробовали Noto Sans
  Regular и SemiBold; у SemiBold с `--peak auto` вес ближе всего).

Проверка веса: `dump --glyph U+0410`, затем сравнить со игровой `A`
(`dump --glyph U+0041`): у игры `max 196`, доля «полутонов» (10..190) — **94 %**;
у хорошей копии доля полутонов тоже 85–95 % (это признак правильного SDF).

## 4b. SDF: что делают флаги

- `build … --sdf auto` (по умолчанию) — глифы пишутся **как SDF**: наклон
  (единиц на пиксель) измеряется по игровым `H`/`A`/`o`, край ставится на 128.
  `--sdf off` — писать «покрытие» (не рекомендуется: буквы резче и жирнее латиницы),
  `--sdf 30` — задать наклон вручную.
- `import … --coverage-to-sdf auto` — если букву нарисовали в редакторе как заливку
  (плоские плато до 255), инструмент сам переведёт её в SDF. Проверено:
  32 % полутонов → **85 %** (у игровой латиницы 94 %).
- `import` без этого флага вставляет PNG **как есть** — это правильно для правки уже
  существующих глифов (они уже SDF, и дамп даёт их истинные значения).

## 5. Тонкая правка: рисовать руками

1. Выгрузить ячейку: `$FF dump <шрифт> <png> --glyph U+0410` (получится ×6).
2. Править в редакторе:
   - **серый = покрытие** (чем светлее, тем плотнее буква), чёрный = пусто,
     белый = 255 (для совпадения с латиницей лучше не превышать 196);
   - не выходить за пределы ячейки 37×42 — всё, что за границей, обрежется;
   - не трогать сетку/поля — координаты ячейки важны.
3. Влить обратно:
```
$FF import work/font/patched/standard.wifnt work/verify/glyph-A-ru.png \
     work/font/patched/standard.wifnt --glyph U+0410
```
   PNG должен быть **кратен ячейке** (×1…×6 — масштаб определяется автоматически).
4. Для правки сразу многих глифов: `$FF dump … atlas.png` (1:1), редактировать,
   затем `$FF import … atlas.png … ` **без** `--glyph` (размеры обязаны совпадать:
   1852×2226 для `standard`).
5. Проверка целостности: `dump` → правка не нужна → `import` → `dump`
   (у меня ячейка и весь атлас возвращаются побайтово идентичными).

## 6. Вкатить в игру и посмотреть в Eden

```
powershell -NoProfile -Command "Get-Process eden -EA SilentlyContinue | Stop-Process -Force"
cp work/font/patched/*.wifnt work/stage/menu/font/
MOD=work/emulator/eden/user/sdmc/atmosphere/contents/010074F013262000/romfs
tools/ardpack/target/release/ardpack.exe --arh "$MOD/bf3.arh" --ard "$MOD/bf3.ard" \
    --out-arh "$MOD/bf3.arh" --dir work/stage --mode append --compress zstd \
    /menu/font/standard.wifnt /menu/font/talk.wifnt /menu/font/ascii.wifnt
powershell -NoProfile -Command "Start-Process -FilePath 'C:\Users\danrus\Documents\xb3-ru-ai-translate\work\emulator\eden\eden.exe' -ArgumentList 'C:\Users\danrus\Documents\xb3-ru-ai-translate\game\game.nsp' -WorkingDirectory 'C:\Users\danrus\Documents\xb3-ru-ai-translate\work\emulator\eden'; Start-Sleep -Seconds 150"
powershell -NoProfile -ExecutionPolicy Bypass -File work/scripts/cap.ps1 -Proc eden -Out work/verify/my-font.png
```

Важные грабли:
- `--arh` должен быть **текущим** (уже пропатченным) ARH, иначе ранее вкатанные
  записи теряются (игра вернётся к оригинальному тексту);
- режим только `--mode append`; `--mode rewrite` переписывает ARH целиком и игра
  на таком файле падает (`Unmapped Read` в логе);
- скриншоты снимать `PrintWindow` (`work/scripts/cap.ps1`) — обычный захват экрана
  ловит терминал, а Vulkan-кадр PrintWindow иногда отдаёт чёрным, тогда повторять.

## 7. Что считать успехом

- Титульный экран: `НОВАЯ ИГРА` по весу и яркости не отличается от `OPTIONS`.
- Длинная строка со всем алфавитом (`АБВГДЕЁЖЗИЙКЛМНОПРСТУФХЦЧШЩЪЫЬЭЮЯ «ёж» — …’`)
  рисуется без обрезки и наложений.
- Если текст слишком широкий — правь не глифы, а `scale_x`/`add_char_space`
  в `bf3_gb.wisty` (это стили: масштаб, максимальная ширина, межбуквенный пробел).
- **Отсутствующий глиф = падение игры** (чёрный экран + шквал `Unmapped Read`),
  поэтому обязательный набор должен быть закрыт полностью — проверяй `audit`.

## 8. Что попадает в мод для консоли

`romfs/menu/font/{ascii,standard,talk}.wifnt` внутри пакета мода
(LayeredFS + `xcnx-file-loader` на Atmosphère). CJK-шрифты
(`standard_cn/kr/tw`) не трогаем. Проверка на консоли обязательна: в Eden лоадер
не срабатывает (это ограничение связки Eden↔Skyline, не наш баг).

## 9. Грабли: ширина глифа, шаг буквы и «Ю», выглядящая как «К»

В LAFT у глифа два поля: `left_x` и `width`. **Их сумма — шаг буквы** (`advance = left_x + width`),
а окно сэмплирования текстуры начинается в `left_x` и тянется на `width`. Поэтому `width`
обязан вмещать чернила *и* правый отступ; если посчитать только чернила, шаг выходит на
~10 px уже игрового и буквы наезжают друг на друга — «Искусства» на экране читается как
«Искусма», «Пользование» как «ПгвепслъзованИ».

Вторая ловушка — как мерить чернила. У SDF рампа вокруг глифа занимает несколько пикселей,
поэтому «любой ненулевой пиксель» завышает габарит по горизонтали. Правильно так:

- **высота и левый отступ** — по «любому ненулевому» (рампа входит в габарит буквы):
  у игровой `H` это `cap_h=28`, `left_x=3`;
- **правый край** — по телу глифа (порог 160): у игровой `H` правый край 25, шаг 32,
  отсюда `pad_right = шаг − правый край = 7`.

Текущая калибровка `fontfix build` даёт `cap_h=28`, `pad_left=3`, `pad_right=7`, то есть
шаг ≈ чернила + 13 px — как у латиницы игры (`H`: 15 px чернил при шаге 32).

Что было не так в первой версии:

1. `width = bearing + ВЫСОТА + pad_right` — где высота ≈ ширина, сходило; у «Ю» круг шире
   кегля (чернила 36 px против высоты 28), окно выходило 31 px, круг отрезался, и на экране
   оставался «К»-образный обрубок (в HUD партии вместо «Юни» читалось «Кини»).
2. Попытка считать ширину строго по чернилам сделала шаг слишком узким и слипшимися все
   буквы — это заметно сразу, по любому длинному тексту в меню.

Починено так: ширина = `bearing + чернила + pad_right`; если глиф всё равно не влезает в
ячейку (`cell_w − left_x`), он рисуется уменьшенным кеглем (`scale *= avail / need`).
Из всей кириллицы подгонка нужна только «Ю»: `ink=36, нужно 46, доступно 34 → ×0.74`.

Проверка: `build` печатает строку `узкий кегль для U+XXXX`, а `fontfix metrics` показывает
`left_x`, `width` и фактические границы чернил по каждому глифу — сверяйте с игровыми
`H`/`A`/`o`/`m`. У самой игры в `msg_mnu_title` есть служебная строка `|3|` со всем алфавитом
и «ёж» — монолитовцы проверяли шрифт так же.

## 10. Проверить шрифт в игре целиком

Временная правка `config/manual_overrides.csv` (приоритет выше кэша) + `apply` → `pack` →
правка архива → запуск. Пример: строка 2 титульного меню = `АБВГДЕЁЖЗИЙКЛМНОПРСТ`,
строка 13 = `УФХЦЧШЩЪЫЬЭЮЯ Юни`. После проверки файл правок удаляется и цепочка
повторяется — в релиз тестовые строки не попадают.

### Высота и базовая линия: чем это ломается

Две ловушки, которые видно только глазами, поэтому сначала собирайте предпросмотр.

0. **Сравнивать только наложением.** В окне предпросмотра `Tab` переключает режим: «рядом» и
   «наложение». В наложении кириллица рисуется зелёным, латиница игры — розовым, совпадение
   даёт жёлтый. Каждая пара букв ставится в общий слот, поэтому сравниваются сами буквы, а не
   накопленная разница шагов. По размеру буквы подбираются до «жёлтого»; сейчас расхождение
   около пикселя (прописные 16.8 против 17.8, строчные 12.8 против 11.8 при `--cap-h 20`).
1. **Высоту мерить по телу глифа, а не по рампам SDF.** Замер «любой ненулевой пиксель»
   даёт у игровой `H` высоту 28 px, а порог 160 — 18 px. Если калибровать кегль по первому
   числу, кириллица выходит примерно на треть крупнее латиницы: буквы сливаются, а «Ю» и «Ж»
   не влезают в ячейку и требуют уменьшения кегля — отсюда «разнокалиберность». Сейчас
   `build` берёт 18 px (порог 160), ручное переопределение — `--cap-h N`.
2. **Базовую линию надо компенсировать.** Игровой шрифт рисует глифы на ~4 px выше
   собственной базовой линии (оптический вынос). Если не скомпенсировать, все наши буквы
   садятся на 4 px ниже латиницы. Лечится `--y-shift=-4` (именно так, с `=`, иначе clap
   примет `-4` за флаг).

Контроль — по нарезанным ячейкам, а не на глаз: `fontfix split` пишет `metrics.tsv`, а
положение чернил по вертикали видно прямо в PNG. Замер после правок:

| глиф | чернила по вертикали | у игры |
|---|---|---|
| `Н` / `H` | 16.0..30.8 | 13.0..30.8 |
| `о` / `o` | 20.0..30.8 | 19.0..30.8 |
| `Ю` | 15.0..30.8 (без подгонки кегля) | — |

Остаётся расхождение по высоте прописных (14.8 против 17.8 px): у Noto другое отношение
высоты прописных к строчным. Строчные совпадают почти точно, и это важнее — строчных в
тексте больше. При желании кегль поднимается флагом `--cap-h`.

### Живой предпросмотр (GUI)

```
tools\fontfix\target\release\fontui.exe --ru work\font\patched\standard.wifnt \
    --en work\font\extracted\menu\font\standard.wifnt
```

Окно с двумя панелями: сверху наш шрифт (алфавит, панграмма, строка с пунктуацией),
снизу оригинальный английский. Масштаб — шаг **0.25** (кнопки и `Ctrl`+колесо), кнопка
«Сброс» возвращает ×2. Файлы перечитываются каждые 0.7 с: сохранили шрифт или отдельный
глиф — картинка обновилась сама. Окно можно унести на второй монитор.

Правка одного глифа: `fontfix split` режет шрифт в PNG (ячейка ×6 + `metrics.tsv`),
рисуете в редакторе, возвращаете `fontfix import --glyph U+0410` — предпросмотр сразу
покажет результат.

Отдельно: собственный глиф игры «…» (U+2026) в её шрифте **приподнят** относительно строки —
это видно и в оригинале, не наш дефект. В английских строках часто стоят три отдельные точки
`...`, отсюда впечатление разницы.

## 11. Скрипт полного цикла: распаковать всё / запаковать всё

```
powershell -ExecutionPolicy Bypass -File work\scripts\font-roundtrip.ps1 -Mode unpack
powershell -ExecutionPolicy Bypass -File work\scripts\font-roundtrip.ps1 -Mode pack
powershell -ExecutionPolicy Bypass -File work\scripts\font-roundtrip.ps1 -Mode both -SkipArchive
```

- **unpack** — режет все три шрифта (`ascii`, `standard`, `talk`) на глифы в
  `work\font\glyphs\<шрифт>\` (PNG ячейки ×6) и складывает эталонную копию в
  `work\font\glyphs_ref\`. Эталон нужен, чтобы `pack` вливал только то, что вы правили.
- **pack** — сравнивает рабочие PNG с эталоном, вливает изменённые глифы цепочкой
  (`fontfix import` по одному), обновляет эталон (повторный запуск без правок становится
  пустым), затем закрывает Eden, вкатывает шрифты и тексты в мод-архив и пересобирает `dist`.
  Флаги: `-SkipArchive` (только шрифты), `-SkipDist` (без релиза), `-Fonts ascii,standard`
  (ограничить набор).
- Проверено: без правок `pack` сообщает «правок нет» и ничего не меняет; при подмене одного
  глифа (взяли игровую `H` вместо нашей `Н`) метрики после вливания совпали с игровыми
  до пикселя — x 11.0…25.8, y 13.0…30.8.

Пока `pack` вкатывает архив, окно `fontui.exe` можно не закрывать: оно только читает файлы
(если окно открыто, Eden всё равно закроется — его держит архив).

### Сглаживание: почему кириллица выглядела «жёсткой»

В LAFT хранится SDF, и число различимых уровней яркости в глифе определяет, насколько мягко
он выглядит. У игровых глифов их **125–177**, полутонов около половины ненулевых пикселей.

Первая версия `build` строила SDF из **бинарной** маски (`v >= 128`) и считала расстояние
целыми пикселями: в глифе оставалось **14–15** уровней — отсюда «ступеньки» на краях, которых
нет у латиницы. Теперь расстояние считается на растре, увеличенном вчетверо, и усредняется
обратно (`sdf_from_coverage_ss`): уровней стало **113–174**, полутонов 55 % — как у игры.

Проверка (без запуска игры): выгрузите ячейку `fontfix split`, посчитайте в ней число
различных ненулевых значений и долю значений в диапазоне 10…190. Хорошая копия: уровней
больше сотни, полутонов 50–90 %. Мало уровней (десяток) — сглаживание потеряно.

Тонкость: после суперсэмплинга внутренность глифа доходит до 255, тогда как у игровых глифов
она ~196. Разницы в картинке нет — шейдер всё, что заметно выше края (128), рисует сплошным;
это просто метка «внутри», а не яркость.

### Шаг буквы: левый отступ и своё многоточие

Две правки, которые понадобились после замечаний «буквы прижаты к левому краю» и «многоточие
висит по середине»:

- **Шаг буквы берётся из самого TTF** (`h_advance_unscaled × кегль / units_per_em`), а не
  считается приблизительно: движок выводит шаг как `left_x + width − global_width_reduction`,
  поэтому `width = родной advance + reduction − left_x`. Иначе буквы либо разъезжаются, либо
  лепятся друг к другу. Проверка: у нашего `Н` шаг 31 против 32 у игровой `H`.
- **Окно сэмплирования обязано вмещать SDF-рампу с обеих сторон.** Край окна обрезает
  рампу, и игра рисует вокруг буквы свечение — без полей оно срезается. Ширина окна берётся
  как `max(шаг TTF, чернила + 2 × рампа)`, буква центрируется в этом окне. Рампа ≈ 5 px при
  наклоне 30, то есть на каждую букву нужно ~10 px запаса. Иглами это правится точечно
  (`--x-shift`), но лучше полями.
- **Порядок подгонки в тесную ячейку**: сначала уменьшается левый отступ, и только если буква
  не влезает даже без него — кегль. Если поджимать кегль сразу (как было сначала), «Ж Ш Щ Ю Я»
  ужимаются на 15-20 % и перестают выглядеть прописными: у всех прописных высота обязана
  совпадать (сейчас 17.8 у `Н, А, О, Ж, Ш, Ю, Я, М` и у игровой `H`).
- `--min-bearing 8` — минимальный левый отступ буквы внутри её шага. У игрового шрифта он
  ~8 px (`H`: чернила начинаются в 11-й колонке ячейки при `left_x=3`), у Noto всего 2–3,
  из-за чего кириллица упиралась в левый край слота, а справа оставался пустой зазор.
  С флагом наш `Н` встаёт как игровая `H`: чернила 12…26 против 11…26.
- `--force-glyphs U+2026` — перерисовать символ, даже если он в шрифте уже есть. Собственное
  многоточие игры приподнято (чернила 21.0…22.8 при строке 30.8), и в русском тексте это
  бросается в глаза, потому что в английском там обычно три отдельные точки. Своё многоточие
  садится на строку: 21.0…30.8. При такой перерисовке ячейка **обязательно очищается** перед
  отрисовкой — иначе новый глиф ложится поверх старого и на экране видно оба (многоточие
  «двоится»). Проверка: в ячейке должна быть одна полоса чернил (`fontfix split`, посмотреть
  строки с ненулевыми пикселями).

Полная команда сборки кириллицы теперь такая:

```
fontfix build work\font\extracted\menu\font\standard.wifnt assets\fonts\NotoSans-SemiBold.ttf \
    work\font\patched\standard.wifnt --peak auto --y-shift=-4 --cap-h 20 \
    --min-bearing 7 --force-glyphs U+2026
```
