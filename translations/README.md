# Выжимка переводов

`ru.jsonl` — все готовые переводы, по одной записи на строку, отсортированные по ключу.
Это публикуемая копия рабочего кэша `work/t9n/cache.sqlite`: кэш бинарный и не годится
для истории в git, а выжимка читается диффами, ищется поиском и правится руками.

```json
{"key":"game/field|621C6EF4|32|name","src":"...","ru":"...","status":"ok","model":"...","prompt_ver":7}
```

| Поле | Значение |
|---|---|
| `key` | адрес строки: `путь\|таблица\|строка\|колонка` |
| `src` | английский оригинал |
| `ru` | перевод |
| `status` | `ok` — строка готова и попадает в сборку |
| `model` | какой моделью переведено (для разбора расхождений) |
| `prompt_ver` | версия промпта на момент перевода |

**Важно:** файл содержит только кэш. Ручные правки лежат отдельно, в
`config/manual_overrides.csv`, и подставляются поверх кэша на шаге `xlat.apply` —
поэтому для полной картины нужны оба файла.

## Зачем это

Из чистого клона репозитория можно собрать мод, не прогоняя модель:

```powershell
cd tools
python -m xlat.import    # translations/ru.jsonl → work/t9n/cache.sqlite
python -m xlat.apply
python -m xlat.pack
python -m xlat.dist
```

## Обновление

```powershell
cd tools
python -m xlat.export                      # кэш → translations/ru.jsonl
python -m xlat.export --corpus ../work/corpus/corpus.jsonl   # с отчётом об остатке
```

Выжимка обновляется перед выпуском версии: она вместе с git-тегом фиксирует, что
именно вошло в сборку. Правки в выжимку руками не вносят — они попадут в
`config/manual_overrides.csv` (см. `docs/EDITING.md`).
